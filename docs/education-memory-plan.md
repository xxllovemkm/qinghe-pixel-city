日期：2026-09-14

用途：交给实施模型执行，由原分析模型在交付后独立验收。本文规定目标、范围、顺序和完成条件；[执行细则](education-memory-execution.md)规定操作、预算、证据和交接格式。现有任务身份继续沿用[任务待办](education-memory-todo.md)中的 A／B／C／V 编号。

## 1. 交付目标

完成一条可运行、可观察、可追溯的青河市学校日：学生从本人住所出发，经城市道路和校区进入对应年级的教室，按照固定课表学习，放学回家，完成完整作业，由个人 APP 批改与连续辅导。教材目录和教学设计决定课程内容；人物设定、真实画像、APP 预测画像随同一名学生的学习经历连接起来。

本轮重点是当前流程的可靠性、课程质量和三天连续验证。最终交付应使验收者能够选中一个学生，逐步核查课程来源、通勤、课堂原答、整份提交、批改、对话、Memory 和两张个人图谱。

## 4. 阶段与验收门槛

阶段编号 P0–P5 只表示本次执行顺序，任务归属仍使用原 TODO 编号。每阶段完成后保存证据并自动进入已满足依赖的下一阶段；发现阻断时保留检查点并继续其他独立工作。

### P0：冻结基线与完成现有运行收尾

对应 V1／V2／C2。先接管可复现状态，再改业务逻辑。

交付内容：

1. 保存前后端分支、提交、工作区差异、已有未跟踪文件、代码哈希和依赖信息。
2. 为历史首日运行、对应评测及图谱来源建立文件哈希清单；修改前后核对一致性。
3. 复现完整路线断言失败。检查当前端点诊断中的浮点差异，采用有尺度依据的坐标容差，并保持场景和路径顺序检查。
4. 在真实浏览器核查回家后六份作业、APP 图谱、节点证据、刷新恢复；保存与最终代码对应的结果。
5. 将已完成的 13 项评测及最终运行结果写回实施说明，逐项记录实际状态。

完成条件：历史档案哈希一致；完整往返路线检查通过；浏览器必测项均有明确结果；当前缺陷可按证据复现。路线容差测试同时包含微小误差通过、明显偏移失败和顺序颠倒失败。

### P1：修整教学目标提取和图谱版本

对应 A1／C1。先保证节点语义与历史身份，再使用新节点产生课程、画像及 Memory。

交付内容：

1. 区分目标正文与独立栏目标题，处理“教学重点、难点”混入目标的已知案例，同时保留原始片段、文件哈希和提取规则版本。
2. 节点的完整原文、显示名称分别保存；名称在 UI 合理截断，详情保留完整原文与引用定位。
3. 图谱发布身份纳入源文件、目录、提取器版本与派生目标内容；历史运行按记录的图谱版本读取。
4. 生成旧目标到新目标的显式对应：不变、一对一变化、拆分、合并、待确认分别表达。状态迁移另记事件及依据，旧档案可重放。
5. 输出全目录覆盖报告；当前三天课段逐项核对教材、年级、学期、单元、课序和目标完整度。长期缺失资料形成定位到文件的清单。

完成条件：已知栏目混入案例解决；抽取回归覆盖正常标题、嵌套标题、多行目标、同文目标和长文本；旧运行可用原版本重开；迁移可重放且结果可解释；三天所选课段的来源检查通过。

整个目录的人工排序确认属于后续范围。本轮必须准确呈现未确认数量及其对可执行课段的影响。

### P2：课程活动、完整作业与评分证据

对应 C1／V1。以现有六学科首课为开发回归集，另冻结每科一个未用于调试的后续课时作为验收集。

交付内容：

1. 教学设计中每个目标对应课堂活动、任务及可观察表现。跨课时目标明确本课覆盖与后续安排，保留整体来源目标。
2. 课堂活动实际执行其声明的任务；题号、活动时长、题目材料、答案量规和目标引用一致。
3. 生物观察、道法采访、朗读等任务具有活动位置、输入、产出和证据类型；已有能力可执行的目标进入当前课段，能力缺口显示为具体的课程阻断。
4. 作业保持 12–20 题的完整形态，题型随学科和目标选择，按整天统筹题目复杂度、预计完成时间和实践任务。
5. 七年级验收样本采用“每日全部作业预计合计不超过 90 分钟”的工程验收预算。该数字是本轮模拟设定；题目时长须有任务分解与依据，不作为实测人类完成时间。
6. 朗读、签字、图片等证据分别记录提交完整性、可判定性、得分和能力证据。将缺少证据、错误答案、部分分、空答、提示后订正分开处理。
7. 保留原教案、失败响应和修复链。局部修复完成后仍执行完整校验。

完成条件：两组六学科课程均有来源到活动的检查结果；开发集所有重大问题完成复核；冻结验收集六课均完成判定，重大课程错误为零，待复核项经独立审查关闭；每日作业负荷满足冻结预算；评分证据专项通过。

冻结集首次结果原样保存。若用于后续调试，则转为开发集并另取等量新课时验收，记录轮次与总预算。

### P3：连续辅导、Memory 与两种掌握状态

对应 B3／B4／A2／A3／C3。

交付内容：

1. APP 提问后存在可恢复的待回应状态；下一条学生消息回答实际收到的问题，APP 依据该回答继续教学。
2. 轮次或预算用尽时保存下一步任务。知识更新区分听过讲解、自述理解、提示下作答、独立作答、迁移及隔日表现。
3. 每条 Memory 和 APP 目标判断可回到本人当前或合法历史证据；跨题关联记录明确的依据关系。
4. 人物设定和模拟器真实状态驱动学生行为；APP 预测由实际可见的本人证据形成。审核实际模型请求中的角色投影。
5. 两张个人三维图分别显示本视角已学目标；所有显示节点具有有限掌握度、星级、时间和原证据。

完成条件：至少六个真实对话案例覆盖错答诊断、部分分、证据缺失、提示后订正、独立变式与跨日接续；每例形成“APP 提问 → 学生回应 → APP 依据回应推进”，或明确保留尚待回应状态。画像证据、重放、角色隔离及 UI 联合检查通过。

掌握公式与星级是声明的模拟／预测量规。本轮验证其实现、证据关系和状态变化，测量有效性单独研究。

### P4：三天有界真实运行与独立评测

对应 V1／V2／C2／C3。P1–P3 的关键问题通过后执行。

固定样本：七年级上册，3 名学生，连续 3 个上课日，每天 6 课，每份作业 12 题。三人使用预先声明的不同初始准备与求助倾向，后续作答由 LiteLLM 根据真实经历产生。

预期主流程分母：18 个共享课时、54 份学生作业、648 道作业题记录、9 次上学与9 次回家。另加入 3 份已冻结、已核对原文的外来材料，每生一份；外来材料题量、请求及批改单独统计。

交付内容：

1. 冻结课表、人物、模型、量规、图谱、外来材料、预算与验收脚本版本。
2. 每天保存学校、住所、事件、作答、批改、对话、Memory 和两种画像快照。
3. 在一天结束后进行一次真实服务重启，从相同运行恢复下一天，并核对已完成提交、请求与画像的身份。
4. 对全部 18 份教案、54 份批改和3名学生的完整对话分别评测，形成75个主任务；三份外来材料分别追加批改和对话复核，共6项。题目复核覆盖648道作业及外来材料的全部选定题。
5. 形成逐学生、逐天、逐课的报告，说明 Memory 在下一步教学中的具体作用和实际学生反应。

完成条件：主流程分母完整，来源与归属检查通过；实际请求、token、错误、拒绝、重试与时间可核对；重大教学问题和评分争议经复核关闭；三天浏览器接续通过。样本未自然出现的错误类型继续标记覆盖缺口，由专项案例补足，保留其不同来源。

### P5：统一交付与独立验收

对应 V2。

交付包必须包含：前后端版本清单、修改范围、运行说明、检查命令、测试结果、真实运行身份、冻结评测、逐项案例、浏览器证据、剩余问题、P0–P4 和原 TODO 编号对照。

由实施模型先自检，再交回本任务。原分析模型将依据执行细则独立抽查代码、档案、实际 UI 和教学案例，给出“通过／有条件通过／未通过”及逐项依据。实施模型提交的报告是验收输入。

## 5. 后续研究范围

以下事项持续登记：全目录人工顺序确认、先修关系教学审核、学期正式考试、复杂图形与音视频能力扩展、各学段大规模个人图、多班高并发性能、掌握阈值校准、Memory 学习收益的配对实验。

本轮应完成当前课段所需能力，并准确标记能力边界。跨人群学习效果与高并发能力需要相应样本和独立实验支持。
